# 官方 API 备用与实际路由

[English](official-fallback.md) | 中文

0.4.1 候选保留默认无需凭据的 SearXNG 搜索和本地 HTTP 抓取。两种新的官方 API 备用均默认关闭，需在插件卡片分别勾选并保存。搜索使用 `allowOfficialApiFallback`，抓取使用 `allowOfficialFetchFallback`；旧 `allowOfficialFallback` 不会自动启用这两种新 API 调用。

| 操作 | 默认路径 | 明确开启备用后的行为 |
|---|---|---|
| `web_search` | `searxng` → 自己的 SearXNG | 主搜索抛出错误后，允许一次直接 Search API 请求 |
| `web_fetch` | `searxng-http` → 目标宿主公开的 HTTP 抓取实现 | 指定失败允许一次直接 Fetch API 请求 |

卡片的「测试搜索」始终只测试 SearXNG，不调用备用。主路径成功、用户取消或开关关闭时，不调用官方 API。异步解析凭据后会再次检查取消和开关；一次官方尝试失败后不继续重试。

## 抓取重试边界

允许重试的情况包括宿主报告的传输错误／抓取超时、HTTP 403、408、429、5xx，以及少量通过页面标题或特定标记识别的验证页。检测是有限的，不保证识别所有反爬页面。官方接口也可能返回错误或验证页；识别出的官方验证页不会作为已恢复的正文交给模型。

URL 不合法、非公网目的地、安全策略、跨源重定向限制或响应大小限制等本地拒绝，不会触发付费尝试。插件不通过备用绕过这些限制。本地抓取直接复用当前目标宿主导出的 `HttpFetchProvider`，并沿用 `web-fetch-http` 的限制和用户代理设置；没有复制一份较旧的抓取器。

## 凭据、费用与隐私

每次准备备用时重新解析宿主公共凭据服务中的 `DEEPSEEK_API_KEY`，不缓存供之后的请求使用。当前会话使用 DeepSeek 账号时，仅通过宿主公开的账号接口获取其已授权端点的令牌。rc.2 中已挂载的 `web-deepseek-api` 配置提供 API 基础地址、密钥引用或字面值；较旧宿主采用官方文档地址和共享密钥引用。缺少凭据会明确失败，且不发起官方请求。SearXNG 实例鉴权与此完全分开，不会把实例请求头转发给官方 API。

开启备用表示同意把失败的搜索词或 URL 发给配置的 DeepSeek API，并承担可能产生的费用。插件只发起直接 Search/Fetch 请求，不额外发起辅助模型轮次。查询不发送用户原始问题字段。官方 API 的计费与模型读取结果产生的 token 费用分开，具体按[官方规则](https://api-docs.deepseek.com/zh-cn/guides/search/#计费)执行。

发出尝试前记录不含凭据的日志；成功结果附中英双语费用提醒；失败报告主路径与官方尝试的状态。不回显原始官方错误正文、密钥、账号令牌或实例鉴权值。API 请求拒绝自动重定向，响应大小和返回正文均有限制。

## rc.2 的内置开关

卡片顶部的「智能体 Web 路由与费用」分别显示搜索与抓取提供方、配置来源、已保存的备用许可和最近核对时间。它区分直接官方 API、官方 Messages 搜索、插件失败后付费备用、本地路径以及费用未知的其他提供方。尚未保存的表单不改变这个状态；关闭插件备用不能阻止宿主直接选择的官方路由。

rc.2 优先读取宿主公开的实时 Web 配置；alpha.2 通过公开 Loader 配置视图读取。宿主未公开自动选择结果或启动时保存的环境变量值时，面板明确标为「费用状态未确认」，不会据此声称免费。读取失败会使旧路由信息失效；可手动刷新，重新进入窗口也会立即重新核对。面板只展示当前 profile 的配置快照，不执行付费探测，也不是账单或扣费拦截器。模型 token、实例自身和独立工具的费用不在其范围内。

「测试搜索」只验证 SearXNG 实例；即使成功且报告显示没有使用官方备用，也不能证明智能体正在走 SearXNG，或账户没有其他费用。

### 被覆盖后恢复插件路由

顶部面板在路由偏离插件时提供「恢复插件路由」。点击后先查看搜索和抓取的变更，再点击「确认恢复搜索与抓取」，把当前 profile 的选择恢复为 `searxng` / `searxng-http`。写入使用宿主公开的配置编辑接口，并重新读取两条路由确认；不发起搜索、抓取或付费测试。默认不自动抢回用户选择的路由。

这是用户主动保存的 profile 选择，停用或卸载插件不会自动删除。若随后需要停用插件，请同时移除这两个字段的用户覆盖，让其余配置层决定路由，或改成已注册的目标提供方；不要删除同一条目中的其他设置。否则会指向已停用的提供方并明确报错，不会静默转向官方付费搜索。

此操作保留已有的官方备用许可；如果以前已开启备用，恢复后失败仍可能产生费用。请先保存或放弃表单中其他未保存修改。确认期间路由或已保存备用许可发生变化时，本次确认失效，需要重新查看。

只读或缺少编辑能力时，按钮不可用，但「手动恢复步骤」始终可展开。若宿主拒绝高优先级覆盖，面板会明确说明 home 配置或启动覆盖需要由配置维护者调整，不会谎报恢复成功。手动时，在当前 profile 的 `cordis.patch.yml` 中修改已有 `web` 条目的两个字段，保留其他字段与条目，保存后重启 DSH 后端再核对：

```yaml
- id: web
  config:
    searchProvider: searxng
    fetchProvider: searxng-http
```

若存在更高优先级的 home 或命令行覆盖，还需在对应位置清除这两个字段的覆盖或设为上述值。之后再次保存内置 Web API 开关，仍可能重新覆盖路由。

rc.2 的「启用新版 Web 搜索 API」选择 `deepseek-search-api` / `deepseek-fetch-api`，其 profile 覆盖优先于插件 bundle。此时 SearXNG 仍可运行和接受测试，但智能体的搜索不会经过它。关闭内置开关会选择出厂路由，不能据此推断已恢复插件路由。

使用本插件备用时，配置应为：

```yaml
- id: web
  config:
    searchProvider: searxng
    fetchProvider: searxng-http
- id: web-search-searxng
  config:
    allowOfficialApiFallback: false
    allowOfficialFetchFallback: false
```

在卡片中分别开启并保存所需的备用。插件不会强制覆写用户已经选择的路由，或接管自定义抓取提供方；路由不匹配时，对应备用不会参与调用。卡片显示当前配置的搜索／抓取提供方，自动选择时会明确标注。

`allowOfficialFallback` 是保留的旧字段，仅供具有公开 `web.searchWithProvider` 的扩展宿主复用其已注册的 `deepseek-official`。标准 alpha.2 与此处核对的 rc.2 没有该方法。新 API 备用不依赖这项宿主接口。

验证使用本地模拟官方 API；没有以真实付费请求证明所有网站均可抓取。宿主、平台与发布包的实际覆盖见对应版本的验证记录。
