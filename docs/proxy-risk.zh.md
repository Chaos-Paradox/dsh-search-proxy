# DSH 进程代理风险说明

[English](proxy-risk.md) | 中文 · 确认版本：`2026-10-19-v3`

这是默认关闭的进程级功能。启用它表示你接受下述风险，不表示插件已验证你的代理安全。插件只连接你已有的代理，不安装代理服务器、不自动寻找本机代理或端口，也不替你设置代理端的访问限制。

## 开关、风险声明与勾选确认

主机与端口在设置页最底部的红色风险区直接可见，默认均为空，需自行填写。Clash 与 DSH 同机时主机填 `127.0.0.1`，端口取自 Clash 的 HTTP / Mixed 设置，普通 Mixed 监听选择 HTTP。只支持无 URL 账号密码的 HTTP/HTTPS 入口；不支持 SOCKS、PAC 或关闭 TLS 校验。

打开开关只发起启用申请，此时代理仍关闭。风险弹窗要求先点击「查看风险声明」，在界面内展开安全边界、进程影响、隐私、移除和限制，然后才开放勾选框。用户勾选接受并点击「确认风险并启用代理」后，后端才能安装代理策略。阅读与勾选是两个不同动作，不再使用两页分别勾选的流程。界面内声明不依赖远端文档链接可用，本文提供更完整的背景和参考链接。

后端记录短期、单次使用、按阶段轮换的授权；最终确认必须显式接受当前声明版本，读过声明不等于已经启用。取消、关闭弹窗或 Escape 会撤销授权，保持关闭；未提交主机和端口保留在当前页面内存中，刷新即丢弃。首次成功启用时，配置、启用状态和已接受的声明版本按 profile 保存到 DSH 凭据存储。之后重新启用插件或重启 DSH，会恢复已开启的代理，不重复要求输入或确认。同一份有效配置可以主动关闭后再次开启；新配置或声明版本变更时才需重新确认。

「已安装代理策略」不证明代理端口可连接或内网限制安全。本开关不联动重启已运行的 SearXNG；该子进程是否使用代理需单独确认。更新插件后，应完整重启 DSH 后端再刷新页面。

## 最重要的安全变化

直接抓取网页时，DSH 校验域名解析结果并固定实际连接地址。经过显式代理时，域名解析和目的地选择交给代理；DSH 不再执行同一套本地公网 IP 检查。私网 IP 字面量仍被拦截，但一个域名最终是否指向内网，需要代理或出站网关在解析后、连接前检查并限制。

如果外部网页诱导模型访问不应访问的域名，代理又允许连接那个内部目标，可能发生内网探测或内部信息读取。实际影响取决于目标网络、访问控制和鉴权要求。自己运行代理不等于它具备这些限制；HTTPS 也不会阻止访问一个本来就不该访问的目标。

这是宿主记录在案的信任委托，相关安全性质仍有社区讨论，不能把设计说明或讨论帖当作已修复公告。[DSH 设计记录](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/architecture/2026-08-27-outbound-proxy-policy.md)、[Discussion #9680](https://github.com/deepseek-ai/deepseek-harness/discussions/9680)。

## 影响与隐私

- 作用于当前 DSH 后端进程，可能影响模型调用、官方搜索、网页抓取、HTTP MCP 及部分子进程；不只影响 SearXNG。宿主策略让回环直连；额外直连主机需自行填写，不接受全匹配通配符或 CIDR。保留原有 `NO_PROXY`，但它只是路由规则，不能替代内网访问限制。
- 使用同一进程的功能可能依赖代理可用性。代理软件关闭、端口变化或出口故障时，相关请求可能失败。代理开关本身不会触发失败后直连或付费备用；搜索和抓取的官方备用由另外两个默认关闭的开关控制。
- 普通 HTTPS 隧道仍执行证书校验；代理能观察连接目标与流量特征，明文 HTTP 内容可被读取。若运行环境已信任解密证书，HTTPS 的隐私条件也会改变。不要为此功能关闭证书校验或导入来源不明的证书。
- 当前面板不接受代理密码。主机和端口仍属于部署信息，不应直接分享浏览器录屏、环境变量或未脱敏日志。状态响应不返回代理地址；错误不回显配置或底层异常。

## 移除、停用和卸载

运行中的代理策略仍属于当前插件实例，不注册系统服务、不更改系统代理、不管理你已有的代理软件。配置、启用偏好和风险确认保存在宿主的凭据存储中，并以当前 profile 隔离，不写 `.env`、shell 或普通 profile 配置。停用／卸载整个 bundle 或退出时，释放当前实例的代理策略、恢复原进程环境并销毁自有连接池；再次启用时恢复已记住且处于开启状态的代理。正在使用该连接池的请求可能被中断。

主动点击「关闭代理并恢复原策略」会保存关闭状态，重启后不自动开启，但保留配置和确认供下次直接使用。「关闭并清除代理记忆」还会删除已保存的配置和确认。卸载保留记忆，重新安装后可恢复；需要删除时请先清除代理记忆。恢复失败会显示错误，用户可检查代理后重试。已有宿主代理仍优先，不因自动恢复而被覆盖。

已有启动环境代理优先，面板不会覆盖或删除它。停用插件后，原有代理若仍然生效属于恢复原状态，不表示插件残留。

清理保证限于本插件持有的策略、连接、内存授权及环境改动：

- 其他已启动子进程继承的环境是副本，无法从父进程追溯撤销。普通工具、外部 MCP 或用户服务可能需要单独重启；插件不会擅自终止它们。插件自有的 SearXNG 服务仍按其生命周期停止。
- DSH `0.2.1-alpha.2` 的公开代理接口不提供多方并发修改的事务回滚。本功能不支持其他插件同时接管进程代理；遇到这种冲突请完整重启 DSH。不能承诺在任意第三方并发修改下同时保留其新策略并恢复旧策略。
- 仅禁用提供方行可能留下搜索路由。恢复默认搜索应停用整个 bundle；手工写入的路由覆盖也需自行核对。

## 启用前建议

确认代理入口可信且稳定；检查所有实际出口是否限制回环、私网、链路本地和元数据目标，包括 IPv6 和地址映射。先在一次性 profile 验证公网读取、模型和必要 MCP、代理故障、插件停用及恢复。敏感内网或云环境应先配置受限出口；未完成这些验证时，不要把点击阅读与勾选当作安全评估通过。[OWASP SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

## 发布去敏

发行内容不包含操作者填写的地址、端口、授权或运行日志。示例不采用维护者的本机代理或测试服务地址。发布前检查实际 tarball，排除开发路径、环境文件和测试 fixture，并扫描构建代码中的固定回环端口。此功能不修改最低宿主要求；兼容性仍以对应版本的验证记录为准。
